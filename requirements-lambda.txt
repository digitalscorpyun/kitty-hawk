# requirements-lambda.txt -- trimmed, pinned runtime set for a possible Lambda ZIP deployment (M6d, planning only)
#
# NOT used by anything yet. The repo's requirements.txt is unchanged and remains the development set.
# Measured 2026-10-02: Linux (manylinux, CPython 3.12) wheels for exactly these 36 packages unzip to
# 173,809,918 bytes (about 173.8 MB), against Lambda's documented 250 MB unzipped ZIP limit
# (see docs/M6D_PLAN_REV3.md).
#
# History: a first 34-package version passed a Windows trim test but failed on real Linux, because
# chromadb imports pybase64 and orjson at load time. Windows had hidden that: removing a package left
# an empty directory that Python treats as a namespace package, so the import succeeded as a stub.
# pybase64 and orjson were added back after the Linux run; the set below then passed.
#
# Limits of that measurement:
#   - Executed once on Ubuntu 24.04 (WSL2), Python 3.12.3, x86_64: POST /agent/run with FakeClient and a
#     SQLite trace store returned HTTP 200 / success, three runs of three, in isolation (only this set and
#     test-only httpx dependencies on the import path). That is not a Lambda execution.
#   - Python 3.12 was selected on 2026-10-03 (documentation-based; not run on Lambda).
#   - Only the success-case request path was exercised. Other paths may need packages removed here
#     (a persistent Chroma client, Postgres/psycopg2, a live watsonx call needing requests, etc.).
#   - 2026-10-03 re-measure: Mangum 0.22.0 (core/lambda_handler.py's adapter) was added, and the first
#     Linux run of the handler test then showed chromadb imports httpx at load time. The earlier 'isolated'
#     run had httpx on the path as a test-only dependency, so it was never in the measured set. httpx,
#     httpcore, h11, certifi and idna are therefore added as runtime packages. See docs/M6D_PLAN_REV3.md;
#     the 36-package figures above are preserved as history.
#   - Versions are pinned from the local development environment; the Linux wheels used were the same pins.
#
